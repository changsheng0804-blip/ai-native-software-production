# 意见清单：不同观点的收集与处置

## 用途

【建议】本清单收集来自不同人、不同时间段、可能相互矛盾的观点、反例与竞争框架，并跟踪每条的处置结果。它的存在理由是仓库的认识论纪律本身：**研究不能只沿一条线索自我确认（相当于理论的"共因失败"）——异质的意见是理论的异质验证来源。** 这与设计原则"生成与验收分离""验证来源尽量异质"是同一件事在研究层面的应用。

## 规则

【建议】

- 新观点优先来自 GitHub 讨论区（按 [讨论模板](../.github/DISCUSSION_TEMPLATE/) 提交），也可来自研究过程中的明确分歧；
- 每条记录：编号、日期、来源、主张、针对的命题、状态、所需证据、处理结果；
- 状态取值：**待核验 / 讨论中 / 已吸收（→位置） / 已拒绝（→理由） / 被反例推翻（→位置）**；
- 吸收进正式文档的观点必须双语同步并带四类认识状态；拒绝与推翻同样记录理由，不删除历史（仓库纪律：失败与反例是研究结果的一部分）；
- 定期整理：随研究节奏进行，建议每 10 条或每轮实验小结时，由维护者或研究 agent 执行。
