# EX-08：持续演进的软件生产对照实验

认识状态：【建议 / Proposal】 · 执行进度：计划，尚未运行<br>
主命题：H1；辅助命题：H2–H5

## 研究问题

相同质量与总资源约束下，当需求和历史持续增加，新生产组织能否减少每个有效功能的人类协调成本，同时避免把负担搬到验收、集成和知识维护？

## 对象与两组

【建议】先选择一个从零建设、确有使用需求的小型信息管理产品，含录入、查询、报表和角色权限。只使用虚构数据和模拟外部接口。具体产品尚未选定。

- A：常规 AI 辅助开发。允许合理模块化、自动测试、文档和共享库，由人协调需求、实现变更与集成。
- B：候选生产闭环。显式任务边界、版本化规则与证据、受控候选生成、独立验收、组合检查、运行反馈进入知识；达到预定条件才升级给人。

两组使用相同起始需求、生成工具能力、质量门槛、计算预算和人工计时口径。A 可以采用成熟工程实践，不能故意设置弱基线。B 的规格、验收器和平台准备时间全部计入。更换工具能力须同轮应用于两组或作为偏差报告。

## 试验节奏

【建议】先做 30 次变更、3 次独立重复的试点；这是起始方案，尚非充分统计设计。运行前冻结最终次数与方案。

| 阶段 | 注入的变化 | 重点观察 |
|---|---|---|
| 起始 | 基本录入、查询、报表 | 分解与验收准备成本 |
| 扩展 | 新功能、共享规则、不同角色 | 局部修改能否保持隔离 |
| 历史 | 旧规则例外、版本兼容、数据结构变化 | 知识与状态能否继承 |
| 压力 | 并发、重复请求、模拟依赖超时、局部故障 | 组合检查、恢复与升级 |
| 继承 | 清空工作对话、换新执行会话 | 是否必须由人补回隐含知识 |

每组执行相同序列；对执行顺序作平衡安排，记录人员熟悉度和前一组对后一组的学习影响。单独保持各组实现与知识，防止把答案直接复制给另一组。

## 验收与防止“只会做已知题”

【建议】运行前由独立于候选生成的过程制定验收集，分公开调试集和隐藏验收集。硬约束、功能正确性与可用性分别记录。只在既定检查点使用隐藏集，禁止把失败详情无记录地不断喂回候选。

验证器也需检查：植入已知错误，观察能否检出；对争议输出进行人工裁定并记录依据。两组遇到同一真实需求遗漏时同步修正规格，保留原始结果与修订理由。

## 指标与口径

| 指标 | 定义 |
|---|---|
| 人类协调成本（主指标） | 需求、分解、规则、审查、验收器、集成、恢复和知识维护的人类分钟数 ÷ 通过独立验收的有效功能数 |
| 有效产出 | 预先登记且通过验收的功能数；零产出时成本比值记“不可计算”，不能记 0 |
| 人工升级比例 | 需人介入的工作事件数 ÷ 全部工作事件数；同时报告事件总数 |
| 跨单元协调 | 每次变更涉及的跨边界决策次数，按预先写明的计数规则记录 |
| 历史知识保留率 | 替换或会话重置后通过的历史规则验收项 ÷ 当次适用项 |
| 验证漏检率 | 未被验收机制拦截的已知植入错误数 ÷ 被评估的已知植入错误数；自然缺陷另计 |
| 全成本 | 准备、生成、验收、集成、运行、恢复、保存与知识维护分别计量；人工时间与计算费用分列，汇总时公开换算 |
| 质量与风险 | 回归缺陷、错误拒绝、权限或状态违规、重复效果及未知结果分别计数 |

复杂度用预先固定的代理指标描述，例如行为验收项、依赖边数、状态种类与历史例外数；不能用代码行数代表全部复杂度。原始记录至少含实验／组／重复／变更编号、时间、输入与版本、成本、检查结果及人工介入原因。

## 分析与判断

【建议】先比较各阶段的有效产出、质量和全部成本，再画累计人工时间与复杂度代理指标的关系；报告每次独立重复、差异范围和失败，不只给平均数。三次试点不足以确认长期增长规律。

正式运行前填写：具体产品、最终变更序列、质量门槛、预算、最小有意义收益、结果判断规则、停止规则。尚未填写的内容必须保持“待定”，不能运行后挑选有利阈值。

在同等质量下，B 按预先规则改善成本可为 H1 提供限定范围支持；优势被验证与集成吞掉则反对相应主张；混合或数据不足则无法判断。一次 B 组获胜不能证明各 RFC 都有效，需分别按 RFC 设计做机制对照。

## 停止与交付

【建议】达到预算、持续无法满足硬约束、发现隔离失效或验收机制失效时暂停。恢复和人工救场仍计入。交付双语报告、方案版本、可运行实现、去敏原始数据、复现步骤和反例。当前数据与结果：尚无。
