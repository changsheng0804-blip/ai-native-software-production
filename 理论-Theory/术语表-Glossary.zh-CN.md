# 术语表

【建议】下表约定本研究中的用法，便于读者与贡献者一致表达，不声称是各领域唯一标准定义。

| 术语 | 中文解释与本文用法 |
|---|---|
| AI 原生软件生产 | 从 AI 参与主要生成环节出发，重新设计工作单位、验收、知识保存与责任 |
| 生产单元 | 有明确输入、输出、范围、依赖和验收办法的一份工作；不固定等于函数或服务 |
| 候选实现 | 为满足同一需求产生、尚未获采用的代码或可运行制品 |
| DRY | Don't Repeat Yourself，避免重复；本文重点是知识权威来源明确 |
| WET | 本文约定为允许局部重复实现；不规定必须复制几次 |
| 契约 / Contract | 单元间关于数据、单位、权限、行为和失败处理的可检查约定 |
| 适配器 / Adapter | 将一方输入输出转换成另一方契约要求的中间实现 |
| 判定器 / Oracle | 判断结果是否符合要求的机制；可能返回合格、不合格或无法判断 |
| 验证器 / Validator | 执行检查的工具或过程；通过检查不代表规格完整 |
| 不变量 / Invariant | 要求在规定操作范围内始终保持的条件 |
| 沙箱 / Sandbox | 限制候选读写、网络和资源能力的隔离执行环境 |
| 状态提交 / Commitment | 改变正式业务状态或产生外部效果，与 Git 保存版本区分 |
| 幂等 / Idempotency | 同一操作重复请求时不重复产生业务效果的要求 |
| 回滚 / Rollback | 恢复到先前版本或状态的操作；能恢复什么取决于具体机制 |
| 共因失效 / Common-cause failure | 不同候选因共享规则误解、来源或依赖等一起犯错；具体相关程度需测量 |
| 收敛 / Convergence | 在明确条件下进入目标集合；需说明状态、过程、前提和时间范围 |
| 自稳定 / Self-stabilization | 特定模型下从非法状态恢复到合法集合并保持；背景见 E01 |
| CRDT | 无冲突复制数据类型，处理特定副本数据的合并；背景见 E02 |
| 人类协调负担 | 为分解、规则、验收、集成、恢复和知识同步付出的人类时间与决策 |
| RFC | Request for Comments，征求意见稿，记录可讨论的设计与验证计划 |
| Issue | 议题，跟踪有完成条件的问题或实验工作 |
| PR | Pull Request，合并请求，可逐项审阅后将修改纳入主版本 |
| 预注册 / Preregistration | 看见结果前写下实验问题、方法、指标、阈值与停止条件 |
